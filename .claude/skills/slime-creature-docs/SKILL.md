---
name: slime-creature-docs
description: How the isekai binary reads a creature doc and a skill into the ontology — the exact field lines, what counts as territory (including back-ticked paths anywhere in the doc), how minds and parents are detected, the shapes onto check enforces and how to clear a finding. Wear when writing or editing anything under .isekai/{elf,orc,slime,kijin}/ or .claude/skills/.
---

- A creature is a folder `.isekai/<rank dir>/<short>/` (dirs elf, orc, slime, kijin, dark-elf); its id is `<dir>-<short>` lower-cased. Its doc is README.md, else `<short>.md`, else SKILL.md, else the first .md. A folder with no .md is a creature without a doc (a note, and a BondTarget finding for anything that names it).
- Fields are `- **Key:** value` lines, first occurrence wins, keys case-insensitive: `Rank` (world.reRank; an ascended rank name on a base dir promotes), `Reports to` / `Orc` / `Elf` / `Parent`, `Territory` / `Zone` / `Owns`, `Minds` / `Mind` / `Wears` / `Hats`, `Verify` (or bullets under a `## Verify` heading, backticks optional — each bullet is run with `bash -c` from the root).
- Territory = the Territory field + EVERY back-ticked token that contains a `/` and no whitespace, anywhere in the doc. So a foreign path in backticks in a trait becomes owns and, for slimes, an overlap finding: write other creatures' paths in plain text, or put a space inside the backticks (a command with arguments is never a path). Paths are normalised: leading ./, trailing /, * and ** stripped, lower-cased; overlap is equality or a `/`-prefix relation.
- Parent = the name in the Reports-to field (rimuru or `<dir>-<short>`); without the field, the first name of the expected parent rank found in the doc, else rimuru for ranks that report to the throne. The bond is truth (slime→orc), verdict (orc→elf) or reports (→rimuru); a parent not on the roster fails BondTarget.
- Minds are skills under .claude/skills, .opencode/skills, .opencode/skill with a SKILL.md; a name whose prefix is not a rank dir (elf-, orc-, slime-, kijin-) is `shared` — the host's tool, not a mind, exempt from MindWorn and laned as "shared". A creature wears a mind when its Minds field names it OR the mind's name appears as a whole word anywhere in the doc — so name only the minds you mean to wear.
- Skill front matter: `name` (equal to the folder), `description` (one line: what it knows and when to wear it), optional `triggers`; then terse bullets; then an empty `## Thoughts` — thoughts live in the mind that was worn, not in the body's doc. The toolbox lanes a mind by its prefix (slime → zone, orc → verdict, elf/kijin → global).
- Shapes `bin/isekai onto check` enforces: SlimeTruth (a slime has exactly one truth edge), SlimeTerritory (slimes' territories disjoint), MindWorn (every non-shared mind has a wearer), BondTarget (every parent has a doc). Output `@S PASS 0 findings · N creatures · M minds · …`; a finding names the shape, the subject and doc:line. Run it after every doc or skill change.
- An orc's territory is its slimes' union or omitted; the kijin and the elf are not checked for disjointness but world.Owner picks one owner per path at the gate, so keep them disjoint anyway. Hazards found in the code go in the traits of the creature that owns the path.
